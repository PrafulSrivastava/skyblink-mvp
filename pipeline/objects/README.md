# Sky objects pipeline

Builds the sky-objects overlay data for the viewer. For each of the five stored patches
(`barnards-star`, `eps-indi-b`, `wise-0855`, `rw-aur`, `r-dra`) it finds the sources in the 49x49 frames, matches
them against CatWISE2020, AllWISE and 2MASS, flags high proper motion, and writes
`public/data/<patch>/objects.json`. The viewer only draws that file (schema: `schema.py` and `lib/sky-objects.ts`).

## Setup

```
cd pipeline/objects
py -3.12 -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
```

## The one network step

```
.venv/Scripts/python fetch_catalogs.py
```

This is the only script that touches the network. It queries IRSA Gator (300 arcsec cone around each patch
centre, `catwise_2020`, `allwise_p3as_psd`, `fp_psc`) over TLS-verified HTTPS and writes 15 trimmed CSVs plus
`catalogs/snapshots.json`. The files are staged in a temporary directory and moved into `catalogs/` only after every
download succeeded, so a failed run leaves the committed snapshots alone. The committed snapshots are what the rest
of the pipeline reads, so you only need this to refresh them.

It may fail behind a proxy or VPN that intercepts TLS. Do not work around that by turning certificate verification
off; run it from a network without interception instead. The only accepted empty result is the R Dra CatWISE cone
(`ZERO_ROWS_ALLOWED` in `config.py`: CatWISE2020 has a hole around that bright star); any other empty table is an
error.

## Build objects.json (offline)

```
.venv/Scripts/python make_objects.py [--patch ID ...]
```

Reads the committed snapshots and the stored `.f32` frames, no network. With no `--patch` it builds all five.
It writes `public/data/<patch>/objects.json`, adds an `objects` entry to `public/data/manifest.json`, and writes
`reports/counts.txt` (one row per patch, the thresholds used and the snapshot date).

Guards, checked per patch. If any fails, the table is still printed and written to `reports/counts.txt`, the exit
code is 1, and no `objects.json` or manifest change is written for any patch:

- G1: unidentified objects are at most 50% of the detections.
- G2: the median CatWISE-to-detection separation is at most 0.6 px (catches a misaligned grid).
- G3: the bundle target is present and known.
- G4: the bundle target of `barnards-star` and `wise-0855` is flagged as high proper motion.

Non-fatal warnings are listed at the end of `counts.txt` (many unidentified, low recovery of bright CatWISE rows,
comparison star offset over 1 px, target not detected).

### Thresholds

All tunable numbers are in `config.THRESHOLDS` (detection S/N, match radii, link radii, proper-motion cut, image-shift
limits, target absorb radius). The values used are copied into every `objects.json` under `thresholds`.
The guard limits are `GUARD_MAX_*` in the same file.

## How the matching works

Detections are claimed once each, in this order: the bundle target's split CatWISE rows are absorbed (rows within the
absorb radius of the target's CatWISE-epoch position, plus rows near the rest of the 2010-2018 track that carry a
proper motion of at least `moving_pm_mas_yr`); the bundle target (forced; it does not take a detection that a
catalogued static star explains better, and it keeps its own AllWISE/2MASS rows); the Gaia comparison star (forced);
CatWISE rows moved to the mean epoch with their proper motion, with AllWISE and 2MASS rows linked by carrying the
CatWISE motion back to their epoch; AllWISE then 2MASS directly; whatever is left is unidentified. A CatWISE motion
that an older row at the static position disproves is dropped (the object is then not high proper motion, and a row
that only matched through that motion is released). Unidentified detections get an image-motion test between the
first and last full visit.

## Tests

```
.venv/Scripts/python -m pytest -q
```

Run from `pipeline/objects/`. The mini cross-match fixture in `tests/fixtures/` is generated by
`tests/fixtures/make_fixtures.py`; the committed outputs are checked byte for byte against the generator. The viewer
side is checked from the repo root with `node --experimental-strip-types scripts/check-sky-objects.mjs`, which also
checks the generated files.

## What the viewer relies on

- Known and unidentified: "known" means a CatWISE, AllWISE or 2MASS row (or a forced Gaia target or comparison star)
  explains the object. "Unidentified" only means no match in CatWISE, AllWISE or 2MASS within the match radius; the
  UI must not call such an object new or discovered.
- High proper motion: catalog proper motion of at least 1000 mas/yr (and, when the error is known, at least 5 sigma),
  or a measured image shift for unidentified objects. `motion_basis` says which.
- Undetected forced objects: the bundle target and comparison star always appear. If nothing is detected at their
  position, `detected` is false, `snr` is null, the position is the catalog position (`target_px` per visit for the
  target), and `undetected_note` says why: `"core masked"` when their pixel is masked in at least half of the frames,
  otherwise `"no detection above the S/N threshold in the frame stack"`. It is null for detected objects.
- Per-visit pixel positions: `positions` has one `png_x`/`png_y` for every visit id in the patch's `target.json`.
  Catalog-moving objects move with their catalog proper motion, image-moving objects between the two measured
  centroids, the rest stay put. Pixel coordinates are pixel centres (the viewer draws at `(png + 0.5) * scale`).
- `ra`/`dec` are positions at the mean epoch of the stack (`mean_epoch_mjd`). The viewer carries them with the catalog
  proper motion to J2000 for the SIMBAD link and to MJD 57170 for the IRSA CatWISE link.

## Going live later

Live fetching would replace the committed snapshots in `catalogs/` by queries for the requested coordinates, and
would need images for those coordinates (the viewer only has the five patches). `catalogs.py` and `match.py` take plain
rows, so the same matching code can run on live query results behind a server. None of that exists yet.
